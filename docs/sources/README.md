# Исходные слайды карт

**`docs/sources/` — место для ОРИГИНАЛОВ владельца**, презентаций и снимков, с
которых снято содержание карт. Оригиналов слайдов DP и MEIO в репозитории пока
нет: содержание этих карт владелец задал текстом, и оно живёт в
`scripts/author/<map>.json` (authoring source, `CONTENT_FROZEN`).

**`docs/sources/generated/` — производные, а не источник.** Там лежат PNG
сгенерированных слайдов — тех самых importer source, которые разбирает
`scripts/import-pptx.py`:

- `generated/dp-slide.png` ← `In.Plan DP process 06-09-2026.pptx`
- `generated/meio-slide.png` ← `In.Plan MEIO process 06-09-2026.pptx`

Нужны, чтобы посмотреть, что видит импортёр, не открывая pptx. Перерисовать:

```bash
python scripts/author/dp.py          # JSON → pptx
soffice --headless --convert-to png --outdir docs/sources/generated \
  "In.Plan DP process 06-09-2026.pptx"
```

## Этот слайд — носитель для импортёра, а не слайд для колоды

Решение владельца от 06.09.2026, отменяющее прежнее ожидание «получим и карту, и
слайд для колоды из одного файла». Причина замерена: входом импортёр считает
только плашку, левый край которой не дальше 1 828 800 EMU (15 % ширины слайда) от
кромки, поэтому все входы всех этапов рисуются общей левой колонкой и тянутся до
своих шагов через весь слайд. Часть этих коннекторов пересекает текст подписей, и
без переноса входов из левой полосы это не лечится — а перенос ломает разбор.
**В колоду такой слайд не годится.** Для показа людям нужен отдельный слайд,
собранный руками; он этому конвейеру не источник.

Раскладка слайда — не содержание: генератор вправе менять координаты, размеры и
переносы строк, но не подписи, порядок, входы/выходы и рёбра (SPEC §3).
